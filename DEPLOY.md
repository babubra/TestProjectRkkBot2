# Развёртывание и эксплуатация

Документ описывает, как устроен прод и что делать в типовых ситуациях.
Проверено на сервере 2026-08-04.

## Где что живёт

Прод — **`C:\Apps\TESTPROJECTRKKOBT2`** на Windows-сервере, Docker Desktop.
Это обычный клон репозитория на ветке `main`.

**Каталог переносить и переименовывать нельзя** без отдельной подготовки: из него
бинд-маунтом смонтированы сертификаты Let's Encrypt (`certbot\conf`) и конфиг
nginx (`.docker\nginx\nginx.conf`).

Всё остальное на сервере — исторические копии, к проду отношения не имеют и
могут быть удалены: `C:\docker-apps\TestProjectRkkBot2`, `C:\docker-apps\RkkBot-main`,
`C:\docker-apps\TestProjectRkkBot2\TESTPROJECTRKKOBT2`.

## Что из чего состоит

| Контейнер | Сервис compose | Роль |
|---|---|---|
| `rkk-bot` | `bot` | Telegram-бот, polling |
| `rkk-map-backend` | `map-backend` | FastAPI, отдаёт `/api/` |
| `rkk-nginx` | `nginx` | HTTPS + статика Vue, проксирует `/api/` в `map-backend:8000` |
| `rkk-certbot` | `certbot` | автопродление сертификатов |

- Домен: **https://turbomap.mooo.com**
- Общая БД (SQLite): том **`testprojectrkkobt2_data`**, внутри контейнеров — `/app/data/your_database.db`.
  Том общий у `bot` и `map-backend`.
- Имя проекта compose закреплено строкой `name: testprojectrkkobt2` в `docker-compose.yml`.
  **Менять её нельзя** — к имени проекта привязано имя тома с боевой базой.
  Раньше имя бралось из имени каталога, отсюда перестановка букв в `obt`.

## Типовые операции

Все команды — из `C:\Apps\TESTPROJECTRKKOBT2`.

### Поменять переменную окружения (прокси, токен, ключ API)

Правится `.env`, пересборка не нужна — код не меняется:

```powershell
notepad .env
.\deploy.ps1 -NoPull -NoBuild
```

Переменные окружения фиксируются в момент создания контейнера, поэтому просто
`restart` не поможет — контейнер нужно пересоздать, что скрипт и делает.

### Выкатить новый код бота

```powershell
.\deploy.ps1
```

Тянет `main`, пересобирает и пересоздаёт только бота. Веб-стек не трогает.

### Обновить всё

```powershell
.\deploy.ps1 -Service all
```

Самая рискованная из операций: пересобирается фронтенд и nginx, то есть под
ударом HTTPS. Делать осознанно и проверять сайт сразу после.

### Посмотреть логи

```powershell
docker compose logs -f bot
```

## Откат

Образ предыдущей версии остаётся в Docker. Быстрый способ вернуться — переключить
код на прошлый коммит и пересобрать:

```powershell
git log --oneline -5
git switch --detach <хеш_предыдущего>
.\deploy.ps1 -NoPull
```

После проверки не забыть вернуться на ветку: `git switch main`.

Том с БД при пересоздании контейнеров не затрагивается.

## Секреты

Единственный источник — файл **`.env`** в боевом каталоге. Он в `.gitignore`
(шаблон `*.env` закрывает и `prod.env`, и подобные) и в репозиторий не попадает.
Состав переменных — в [.env.example](.env.example).

Если `.env` потерян, а контейнер ещё жив, переменные можно вынуть из него:

```powershell
(docker inspect rkk-bot | ConvertFrom-Json)[0].Config.Env
```

## Нештатные ситуации

**`container name already in use` при деплое.** Контейнер поднят мимо compose
(через `docker run`). Скрипт ловит это заранее и подсказывает команду. Старый
контейнер именно переименовывают, а не удаляют — пока новый не проверен, он
может оказаться единственной копией рабочей конфигурации:

```powershell
docker rename rkk-bot rkk-bot-manual; docker stop rkk-bot-manual
```

**Скрипт ругается на отсутствие тома `testprojectrkkobt2_data`.** Значит сбито имя
проекта compose. Не продолжать: в этой ситуации compose создаст новый пустой том, и
бот поднимется с чистой базой. Проверить `name:` в `docker-compose.yml` и `docker volume ls`.

**Сайт отдаёт 502 после обновления бэкенда.** nginx закешировал старый IP контейнера.
Лечится перезапуском (`.\deploy.ps1` делает это сам, если обновлялся `map-backend`):

```powershell
docker compose restart nginx
```

**Бот не стартует, `ConnectionRefused` к `api.telegram.org:443`.** Telegram блокируется
в РФ — проверить `TELEGRAM_PROXY` в `.env`. Формат: `socks5://логин:пароль@хост:порт`,
спецсимволы в пароле нужно percent-энкодить (`@` → `%40`).

## Про кодировку скриптов

`deploy.ps1` и `dev.ps1` хранятся в **UTF-8 с BOM**. Windows PowerShell 5.1 без BOM
читает `.ps1` как ANSI: кириллица бьётся, а байты `0x92`/`0x94` он принимает за
типографские кавычки, и скрипт перестаёт разбираться с ошибкой вида
«в строке отсутствует завершающий символ». Если редактор сохранит файл без BOM —
скрипт сломается. Правило закреплено в [.gitattributes](.gitattributes).

## Известный технический долг

- **В [app_bot/bot.py](app_bot/bot.py) для прокси-сессии отключена проверка TLS**
  (`check_hostname = False`, `verify_mode = CERT_NONE`) — наследие прокси с самоподписанным
  сертификатом. При SOCKS5 прокси TLS не терминирует, так что заглушка не нужна и её
  стоит убрать: сейчас трафик к Telegram API уязвим к подмене на стороне прокси.
- **nginx резолвит `map-backend` один раз при старте** — отсюда обязательный перезапуск
  после пересоздания бэкенда. Лечится `resolver 127.0.0.11` + переменной в `proxy_pass`.
- **Прод завязан на Docker Desktop с интерактивным входом** — после перезагрузки
  сервера контейнеры не поднимутся, пока никто не зайдёт по RDP. Для боевого сервиса
  это слабая опора: правильнее Docker Engine как служба (или Linux-хост).
- **Три тома с данными** (`testprojectrkkobt2_data` — боевой, плюс `testprojectrkkbot2_db_data`
  и `rkkbottest_data`) и десяток анонимных. Перед чисткой каждый надо проверить.
